# Kitty的小食堂

一个给自己家用的微信小程序：家人点菜，大厨接单，买菜清单自动合并。

不是商用点餐系统，没有支付、没有门店、没有会员体系——就是一家人吃饭前少吵两句"今天吃什么"。

## 能做什么

**家人端**

- 六个菜系：家常炒菜 / 火锅 / 烧烤 / 面点主食 / 甜点饮品 / 凉菜下酒，共 67 道菜
- 火锅按火锅店的方式点：先挑锅底（最多两个，鸳鸯锅正好），再挑涮菜
- 每道菜有热量、用时、辣度、食材用量
- 写口味备注、选开饭时间，提交后大厨手机上就能看到

**厨房端**（口令进入）

- 看当天所有订单，按「待接单 → 烹饪中 → 已上菜」推进
- 买菜清单自动跨订单合并去重，一键复制
- 菜单管理：上下架、调顺序、改菜品、加新菜（可拍照）、删除

## 本地跑起来

用微信开发者工具导入 `family-order` 目录即可，AppID 用自己的或选测试号。

`npm install` 只服务于 `tools/` 下的脚本（图片压缩、校验、测试），小程序运行时不依赖任何 npm 包。

```bash
node tools/validate.js        # 静态校验：资源引用、class 覆盖、包体积
node tools/test-menu.js       # 菜单数据层单元测试（假云端）
node tools/test-live.js       # 连真实后端的冒烟测试（会写数据，用探针菜清理）
node tools/test-security.js   # 权限验证：直连写应失败，带口令 RPC 应成功
node tools/compress-dish-images.js  # 菜品图重新压缩
```

## 云端

数据在 PostgreSQL（通过 PostgREST 暴露），两张表：

- `orders`：订单（谁能读，谁就能看到全家的单）
- `dishes`：菜单（67 道菜 + 你自己加的）

菜单读取有三级兜底：云端 → 本机缓存 → 内置数据。断网也能点菜，云端挂了不会白屏。

## 安全说明

**密钥是混淆，不是加密。** `utils/config.js` 里的发布密钥由 `key-a/b/c.js` 三份倒序分片拼出，只是避免它以明文出现在公开仓库里。任何人拿到仓库都能拼回来——所以真正的防护做在服务端：

| 对象 | anon 能做什么 |
|---|---|
| `dishes` | 只能读；增删改必须走带口令的服务端函数 |
| `orders` | 能读、能下单（INSERT）；改状态必须走带口令的函数 |

即使密钥泄露，攻击者也只能往订单表里塞假单，**改不了菜单、动不了已有订单的状态**。

口令不写在代码里，存在数据库 `app_secret` 表（md5 + 盐），由 `admin_check()` 校验。想换口令：

```sql
update app_secret
   set v = md5('新口令' || 'kitty-canteen-2026')
 where k = 'admin_pin_md5';
```

改完家人不用做任何事，厨房页重新输一次新口令就行。

**没有账号体系。** 谁知道口令谁是厨师，订单对知道密钥的人可见。家用足够，不适合当公共产品。

## 已知限制

- 菜品图是整包内置的（约 1.4MB），加上代码已占 2MB 限额的 80%。再加图要考虑分包或降画质。
- 自建菜的图以 base64 存在数据库里（云存储上传通道不支持二进制），每道约 30KB。
- 微信原生 `<picker>` 在部分预览环境不响应，所以表单里的菜系/分类/辣度都改成了点选标签。
